# 闯关题目缓冲池

## 体验与边界

新题库按固定关卡分两批准备，而非无限出题：首批目标 10 题（1 屏配对、5 屏认词、4 屏听力），后半批最多 10 题（填空/阅读最多 7 题、跟读最多 3 题）。模型返回的有效题目不足时显示真实数量，不重复填充凑数。历史/导入题库保持原样，不受新题库 20 题的限制。

学习详情页沿用 2.5 秒停留预热，但只预生成首批。开始答题后，尚未消耗的认词/听力题剩余不超过 5 题时申请一次后台补题。补题只追加后续关卡，不重排正在做的题目，不清空 XP、难度反馈或已完成进度。错题重练不消耗新题库存。

冷启动仍需要一次真实推理；该功能缩短首批输出、把后半批推理与学习过程重叠，不承诺所有首次请求一秒内完成。它优化的是文本出题，不代替 TTS 下载/设备语音启动的优化。

## 接口

- `POST /api/quest/:id`：明确进入闯关时准备首批；已有题库直接读，活动任务返回 202。
- `GET /api/quest/:id`：只读题库、进度和缓冲状态，绝不触发 AI。
- `POST /api/generation/quest/:id`：原有详情预热；传 `{ "refill": true }` 才申请后半批。
- `POST /api/quest/:id/complete`：用户明确点击「准备后续题」时的交互生成。自动轮询不调用此接口。

前端只读轮询间隔 1.5 秒，最多 80 次。页面隐藏时暂停请求，恢复时接续单条轮询链。卸载、切换练习或重试会使旧响应失效。离开页面不再申请新批次；已提交/开始的有限任务可能继续完成并保存。

## 预算

继续保留每用户每天 3 个、全站每天 12 个**后台批次**的上限（UTC 自然日）。首批和后半批各占一个任务，失败也占位，不因刷新退还以防重试风暴。与此前整套一次生成不同，一套新题库自动完成可能占两个批次。应用文本/分钟调用达到 70% 安全线时不再后台推理；这是调用次数保护，不是 Neurons 精确计量，更不是付费账号零账单保证。

后台仅使用 Cloudflare 文本提供方，不自动降级 Gemini。预算不足、提供方不符或失败时已备题仍可练，后续需要用户明确请求，并遵循所选提供方及原有交互限额。拆批会增加一次请求及部分提示词开销；收益来自更早开始学习、未学后续不生成，而不是声称相同整套内容必然更省 token。

## 一致性与故障

D1 条件 INSERT 原子预留额度，执行时不再把已经预留的本任务当成新的额度申请。`generation_jobs` 的唯一键包含阶段类型 (`quest` / `quest_tail`)，Queue 重投共用原任务；最多三次执行尝试以 D1 计数为准。

HTTP 和 Queue 共用 `quest_generation_locks` 租约。所有保存/清理操作核对 owner，避免旧请求覆盖新持有者；保存时重查课程归属，已删除课程不会被在途请求复活。租约用于故障恢复，不声称能保证模型提供方精确一次扣费。

迁移 0020 给旧题库默认标记 `complete`，扩展任务类型时复制原有 ID、状态和数据，再替换任务表，保留已经排队的消息引用。回归测试覆盖旧进度/队列 ID 保留、真实 SQLite SQL、HTTP/Queue 并发、额度并发和失败恢复。
